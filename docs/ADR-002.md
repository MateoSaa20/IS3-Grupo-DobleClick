# ADR-002 Incorporación de Redis para reducir la latencia de consultas

**Estado:** Aceptado

**Fecha:** 2026-06-09

**Decisores:** Juan Pablo Mencia, Saavedra Fabio Mateo 

Relacionado: Issue #2, métricas de rendimiento, especificación técnica v2.0

## Contexto

* Durante las pruebas se detectó una alta latencia en consultas frecuentemente ejecutadas.
* La base de datos recibe una carga elevada debido a solicitudes repetitivas sobre información poco cambiante.
* Se requiere mejorar los tiempos de respuesta sin modificar la lógica principal del sistema.

## Decisión

* Se decide incorporar Redis como sistema de caché para almacenar temporalmente resultados de consultas frecuentes.
* La caché se aplicará únicamente a operaciones de lectura.
* No se utilizará Redis como almacenamiento persistente principal.

## Alternativas consideradas

### Opción A: Redis

**Pros**

* Muy bajo tiempo de acceso.
* Fácil integración.
* Reduce significativamente la carga sobre la base de datos.

**Contras**

* Incrementa la complejidad de la infraestructura.
* Requiere estrategias de invalidación de caché.

### Opción B: Optimización exclusiva de consultas SQL

**Pros**

* No agrega componentes adicionales.
* Menor complejidad operativa.

**Contras**

* Puede no resolver completamente problemas de alta concurrencia.
* Beneficio limitado en escenarios de crecimiento.

### Opción C: Escalamiento vertical del servidor de base de datos

**Pros**

* Implementación sencilla.
* No modifica la arquitectura existente.

**Contras**

* Incrementa costos de infraestructura.
* Escalabilidad limitada a largo plazo.

## Consecuencias

### Beneficios esperados

* Disminución de la latencia de respuesta.
* Reducción de carga sobre la base de datos.
* Mejor experiencia de usuario.

### Costos o riesgos que se aceptan

* Necesidad de administrar un componente adicional.
* Riesgo de inconsistencias temporales debido a la expiración de caché.

### Impacto en operación y equipo

* Requiere monitoreo adicional.
* Necesidad de conocer conceptos básicos de administración de Redis.

## Plan de implementación

### Pasos mínimos para ejecutarla

1. Desplegar una instancia de Redis.
2. Integrar el cliente Redis en el backend.
3. Identificar consultas candidatas para caché.
4. Definir políticas de expiración.
5. Realizar pruebas de rendimiento.

### Dependencias

* Infraestructura para Redis.
* Soporte del framework backend para caché.

### Métrica de éxito

* Reducción de al menos un 40% en el tiempo promedio de respuesta.
* Disminución del número de consultas repetitivas a la base de datos.

## Triggers de revisión

### Qué condiciones obligan a reabrir esta ADR

* Cambios importantes en el patrón de uso del sistema.
* Problemas de consistencia asociados a la caché.
* Incremento significativo de costos operativos.
